# 实施发现

- 当前正式库 `collection_item` 为 0，收藏规则修改不需要迁移现有业务数据。
- 正式数据库只读审计正常；所有写入回归必须继续使用临时副本。
- 当前 `templates/_media_cards.html` 有用户未提交的类别卡片视觉修改，后续补丁需避开或保留该行。
- 对“下一集”的实现按媒体可用性处理：从最新完成单集之后选择首个有可播放文件的单集；若不存在后续可播放单集，则保留最后一集并从头播放。
- 源码凭据已移除，但曾暴露的 AList/TMDB 凭据是否已在外部服务轮换无法由仓库内修复确认，仍需人工轮换。
- 用户澄清：最近观看卡片继续展示最新历史单集；若该集完成，点击卡片进入详情后，默认选中、默认播放按钮与直接播放入口都应切换到下一集。现实现仅将按钮 action 指向下一集，详情仍选中历史单集，且卡片直接播放仍指向历史文件，语义没有完全统一。
- 最终验证期间正式库出现新的 playback_id=18：小谢尔顿 S3E13/file 226，position=1125656、duration=1191838、watched_at=2026-08-30 11:21:27 UTC，恰好对应用户描述的完成记录；因此正式库哈希从先前快照发生变化。自动化 mutation 仍全部使用临时库，正式库验证请求未跟随 307 到播放 route，不应回滚这条并发产生的真实观看数据。
- Top 3 使用 `_media_cards.html` 的 ranked `backdrop_card` 分支。模板虽然输出 Logo，却仍在下方 content 中输出标题和 subtitle（年份）；CSS 已定义 `.ranked-feature-content { z-index: 2 }`，但模板没有使用该类，导致 z-index=1 的渐变蒙版覆盖 Logo/文字。修复应复用现有类而非增加新的视觉体系。
- Windows 已安装 Edge，Playwright CLI 支持 `--browser msedge`，无需下载 Chrome。当前 ranked Logo CSS 只有尺寸/fit，没有 left/bottom/z-index，位置依赖 static position；应把 Logo 放入左下内容容器，由 flex 布局定位。
- 修复前 Playwright snapshot 确认 Top 3 可访问树的左侧内容为电影名和年份，右侧只有评分，和用户描述一致。前三项分别为挽救计划、星际穿越、河狸变身计划。
- 修复前 1440×1000 截图确认：三张横卡实际只显示标题/年份/评分，Logo 完全不可见，蒙版压暗了全部底部信息。正式库前三部均有本地 logo 路径，因此问题是模板/CSS 层级和定位，不是数据缺失。
- 当前修复期间 `viewmodels/title.py` 的续播文案被并发改为简化形式（“继续播放 10:00”/“播放 S3 E14”），文件时间与本轮 UI 编辑相邻，但本轮未修改该文件。该文案不属于 Top 3 范围，应保留现状；测试改为验证续播 episode/file 身份而不是锁死措辞。
- 详情页底部目前是 Bootstrap `row` 下的 `col-lg-7` 作品信息与 `col-lg-5` 当前播放文件，外部链接嵌在作品信息 section 内。用户要求仅需调整模板顺序：两个 section 改为全宽纵向排列，链接从作品信息移出，作为 `detail-information` 最后一个区块；不需要 ViewModel/CSS/JS 新逻辑。
- 新服务下的 Top 3 snapshot 已不再包含电影标题文本，三卡只保留右侧年份/评分和装饰性 Logo；全卡详情链接仍可访问。需用截图确认 Logo实际可见、蒙版没有压在内容上。
- Top 3 修复后 1440×1000 截图确认：三张 Logo均清晰位于左下，年份与星级评分位于右下，渐变在内容下方且没有遮挡；排名数字、横卡比例和下方海报网格未受影响。
- 电影详情页修复后 snapshot 的末尾结构严格为：region“作品信息” → region“当前播放文件” → navigation“外部链接”；IMDb/TMDB 是页面最后的交互内容，播放按钮与顶部信息保持不变。
- 电影详情 1440×1000 底部截图确认：两组 definition list 全宽纵向排列，字段列线对齐；外部链接在分隔线后位于页面最下方，没有与作品信息并排或夹在中间。
