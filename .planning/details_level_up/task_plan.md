# 详情页层级优化

## 目标

采用方案 B 的数据量与方案 A 的视觉风格，优化电影和剧集详情页的信息层级、栅格布局、季组织及多版本播放入口。

## 阶段

- [complete] 核对详情页现有模板、CSS、数据查询与测试契约
- [complete] 扩展 Model 层详情数据：核心元数据、季组织、多版本资源
- [complete] 重构 Jinja 详情页：克制 Hero、中密度资料、季选择与版本选择
- [complete] 精简并补充必要 CSS/JS，保持 Bootstrap 为主
- [complete] 更新测试并完成静态、模板与回归验证

## 结果

- Hero 保持 3/9 栅格、大 Backdrop 与 Logo 主视觉，新增核心元数据、Tagline、简介、当前播放单集和进度。
- 次级媒体信息下沉到 Hero 以下；电影提供版本列表，TV 使用季 Tabs、单集卡及多版本 Dropdown。
- 数据库无需迁移；详情查询完整返回生产库 13 个电影 source、715 个 TV source 与 490 集，222 个多版本单集全部保留。
- 12 项单元测试通过；生产库 9 个电影和 22 个剧集详情路由全部返回 200；diff 空白检查通过。

## 设计边界

- Hero 保留大 Backdrop、Logo、播放主操作，不加入竖版海报。
- 首屏仅展示高价值核心数据；制作公司、国家、语言、外部链接放在首屏以下。
- 多版本初期使用已有文件名/路径生成可读标签，不虚构分辨率、HDR、编码等尚未结构化的数据。
- 剧集按季组织；单集简介不直接全部铺开。
- 使用 Bootstrap 原生组件和工具类，仅保留必要自定义 CSS。
- 不使用 design-taste-frontend skill，不进行视觉检查。

## 错误记录

- 一次尝试在同一补丁中删除并重建 `templates/detail.html`，工具拒绝同路径多操作；改为两个连续的原子补丁完成替换。
- 首轮模板回归有 1 项失败：旧测试要求年龄分级标签和值为连续文本；新定义列表将两者分栏。已改为分别断言，并补充新详情层级与多版本测试。
- 最终定位行号时 PowerShell 将双引号正则拆成路径，`rg` 返回 Windows 路径语法错误；改用单引号正则重新执行，不影响代码与验证结果。
