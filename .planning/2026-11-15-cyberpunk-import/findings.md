# 夸克剧集关联失败、扫描与删除偏慢：排查记录

对应提交 `025579f`（关联按文件保留成功、探测走分块）、`f772a63`（扫描跳过无视频目录）、`e79f6ff`（删除检查提速、探测小分块多连接、每页 500 条、旧失败任务自动结清）。排查与实现先由 Codex gpt-6.1-sol（high）完成三轮，之后由 Claude 直接处理。

## 关联失败（赛博朋克：边缘行者 S2）

- 表面现象：ffprobe 报 `Server returned 5XX`，一集失败后整部剧“未写入”。
- 5XX 来自本机 `/stream`：内置夸克取流出错时统一回 502，原始异常未记录（现已记录脱敏的阶段、异常类型、上游状态）。
- 真正卡住的原因：`_buffered()` 对 `MovieDB-Probe` 走 `_single()`，把 ffprobe 的 `Range: bytes=0-` 原样转给夸克。实测同一文件限长 10MB 请求 0.6 秒首字节、1.5 秒读完；不限长请求 10.5 秒首字节、30 秒只拿到 2MB 后停住，所以每集 60 秒超时。改走 `_segmented()` 后三集各 2.4–3.4 秒读完。
- 夸克按连接限速：某些分享文件单连接约 130–200KB/s，3 条连接合计约 420KB/s，6 条约 1MB/s。MP4 的 moov 在文件末尾（3.8MB）时，4MB 分块要 30 秒才回首包，因此探测改为 512KiB、4 条连接（夸克当时恢复不限速，未能在限速下实测）。
- 一集失败取消整批：`_prepare_items()` 遇到第一个探测异常就取消其余；关联流程现按文件提交，手动 JSON 导入仍整批原子。

## 删除前检查慢

SQL 只要 5ms，但 `query_title_deletion` 取了全库 1867 条图片引用，`_plan()` 对每条做 `resolve()` 和逐级上级目录检查（约 3 万次 `_getfinalpathname`），每部 5–7 秒。改为只取本作品及共用文件的引用、同一路径只解析一次后为 50–220ms，删除计划与原来逐项一致。

## 扫描慢

全量刷新 75 个顶层条目 164 秒、夸克请求约 2900 次（单次中位 0.15 秒）。按累计耗时：没有视频的目录（电子书、软件）占约 74%，视频已全部关联的约 16%，有待关联的仅约 10%；“Kindle 书库”一个目录 189 个子目录、4603 个文件就要 192 秒。已做：按顶层目录统计耗时并提示“以后跳过”、忽略的目录不再展开、每页 500 条。未做：按目录修改时间跳过未变化的目录（需先确认夸克是否在深层内容变化时更新上级目录时间）。

## 脚本

- `probe_trace.py`：取某任务第 N 个文件的 `/stream` 地址，带探测标识跑 ffprobe，逐行打印每次 Range 请求的时间点（签名打码）。脚本里写死了当时的任务 `16a1d84b`，复用时改成要查的任务。
- `scan_profile.py`：只读地按扫描方式列一遍扫描根目录，统计夸克请求数、耗时分布和各顶层目录是否值得扫。
- `watch_scan.py` / `watch_jobs.py`：轮询扫描状态 / 关联任务进度，状态变化时打印带耗时的日志。
- `prompt.md`、`r2.md`、`r3.md`：交给 sol 的排查任务与两轮返工意见。
