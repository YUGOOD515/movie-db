# 演员剧照展示

## 目标

基于现有 MovieDB 的数据库、查询/路由和详情页链路，实现最小可行的演员剧照展示，并完成生产库迁移、回填与验证。

- [complete] 核对详情路由、查询层、ViewModel 与模板结构
- [complete] 形成数据库、路由、前端三层实施计划与边界
- [complete] 编写可审查迁移 SQL，并扩展测试 schema/fixture
- [complete] 扩展 TMDB 元数据、图片下载与原子写入链路
- [complete] 扩展详情查询、ViewModel、Jinja 与 CSS
- [complete] 运行自动化和浏览器验证
- [complete] 经用户批准后备份、迁移并回填生产 `library.db`
- [complete] 将演员轨道改为与主页、详情页剧照一致的全宽滚动和共享边缘对齐
- [complete] 以详情页单列按钮为单位统一演员卡片宽度和模块网格

## 决策原则

- `imdb.db` 保持只读。
- 复用当前“查询 -> ViewModel -> Jinja”链路。
- 优先扩展已有表/页面；仅在真实数据关系需要时增加最少的新表。
- 第一版只做标题详情页的主要演员横向列表，不做人物详情页、人物搜索或单集客串演员。
- 采用单表 `title_cast`；等出现跨影片人物页等真实需求后，再拆 `person_basic`。
- 前端复用现有 `media-rail` 结构；标题和首张卡片共享 `container-xl` 左边缘，轨道向视口右侧延伸。
- 演员卡片宽度等于详情页的一列单位；播放按钮和选集卡片保持“两列单位加一个标准间距”。

## 错误记录

- Playwright CLI 默认启动 Chrome 失败：本机指定路径没有 Chrome。改用已安装的 Edge，不下载额外浏览器。
- Edge 拒绝访问 5061（浏览器保留的不安全端口）。停止该测试服务并改用 5080。
- 首次直接运行回填脚本时项目根目录不在 `sys.path`，导致找不到 `connectors`；按现有独立脚本模式显式加入项目根目录。
- 将清理与数据库核验组合在一个 PowerShell 调用时被安全策略拒绝；拆为独立、显式绝对路径的清理和只读核验命令。
- 一次删除三个已核验 QA 路径仍被安全策略拒绝；继续拆成单目标命令。
- 首次回填后汇总 SQL 使用了 SQLite 关键字 `cast` 作为别名，解析失败；改为 `actor` 后重新执行只读核验，生产数据未受影响。
- 首轮 38 个标题请求均成功，但一个剧集的普通 `credits` 为空；核实 `aggregate_credits` 有 38 人，修复共享 TMDB 演员入口后重跑回填。
