# 夜间调研与走查发现（2026-11-14）

## 工作项 2：《赛博朋克：边缘行者》进不了“可确认”

只读查看本机 `local.db`（recognition / scan_snapshot / name_alias / import_job）得到：

- 目录 `/Quark/来自：分享/B.【4K.完结.全10集】缘行.者.S02` 下有 4 个画质目录，命名各不相同：`赛博朋克 边缘行者.S02E01…`（SDR）、`Cyberpunk.Edgerunners.S02E01…`（DV.HDR）、`S02E01.Last.Chance.for.a.Slow.Dance…`（HDR、Dobly，只有单集标题）。
- `media_grouping.conflicts()` 不允许把不同文件片名合在一组，AI 分组只能按命名拆开，并把拆出的组标成 `review=true`（不确定）。`recognition_harness.plan_groups` 把它记成 `grouping_review`。
- `recognition.finish()` 只要看到 `grouping_review` 就无条件加“目录分组仍需核对”，状态变成 review。随后补查 harness（`repair`）在校验里再次调用 `finish()`，这条问题身份核验永远修不掉：AI 只要不返回 review 就被打回，最后只能返回 `review: true`。识别记录里可以看到：标题、季集都对上（coverage 1.0、0 个未匹配），却停在“待核对”，问题只有“目录分组仍需核对”。
- 只有 SDR 那组 AI 没标 review，进了“可确认”；其他三组都卡住。用户之后已手动关联了其中 30 个文件（library.db 的 media_file 有记录）。

修复（提交 aa34947）：剧集的每个文件都对上该作品的单集、片名一致、没有其他问题且置信度 ≥ 0.8 时，视为分组已被季集核对证实，不再加这条问题；电影没有季集佐证，仍需核对。harness 测试按这个目录布局补了用例（打桩，不联网），并保留“季集对不上 / 电影”仍需核对的反例。

注意：本机识别缓存的签名不含这段逻辑，已缓存的 review 结果不会自动刷新；需要对相关行点“重新识别”，或提升识别版本号让下次扫描全部重识别（会重新调用 AI，见 progress.md 的“待用户决定”）。

## 工作项 4：代码审核

两个只读审查子 agent（路由 + services；queries/models + JS + CSS），每条我都读代码或用浏览器复现后再处理。

已修（提交 4bd4ba7）：
- `media_discovery`：目录在两次扫描之间被删除 / 改名时 `media_source` 抛 `FileNotFoundError`，没被捕获，整次扫描变成“失败”、其他目录也不扫。现在只记一条读取失败（加了测试）。
- `media_discovery`：识别线程出现意料之外的异常会让已扫完的整次扫描变成失败；现在记日志、保留结果并提示“部分条目未识别”。
- `media-association.js`：编辑器提交成功后没有解锁，下次打开时“待关联”返回、规则、季号等按钮仍是禁用的，只能刷新页面。
- `drives.js`：扫码登录点“重新获取”或关闭弹窗后，已发出的那一轮轮询返回时仍会续命，旧二维码扫码成功还会保存到已重置的表单。改为每次获取一个编号，作废旧轮询。
- `style.css`：`.btn-link`（目录浏览面包屑、状态栏“查看”）悬停变成 Bootstrap 蓝（深色 #8bb9fe / 浅色 #0a58ca，浏览器实测）；识别规则里的季号用了 info 青蓝。都改成中性强调色。
- `style.css` G2：`.ui-card`、`.settings-banner`、`.drive-modal .modal-content` 实测是普通圆角，补上超椭圆；胶囊按钮（chip、genre、分段控件、概览/关联搜索框、紧凑主按钮、目录胶囊）、首页轮播圆钮与圆点、开关实测继承了全站按钮的超椭圆（两端被压扁），按 G2 例外改回 round。
- 死代码：`media-association.js` 里刚置空就判断的 `file.issue`。

核实后没有改（理由）：
- 分段流式传输中途失败时“干净结束”（`media_stream.py` 约 146 行）：审查认为应抛错让连接以未完成关闭；但现有测试 `test_segmented_stops_if_later_part_loses_range_support` 明确断言返回已取到的部分，是有意设计。列入待用户决定。
- 删除作品时先取消关联任务再提交删除（`title_deletion.py`）：审查建议挪到提交之后，但先取消是为了防止正在跑的任务在删除后又写回，挪后反而有竞态；提交失败的概率很低，不改。
- 重扫期间排队中的关联任务可能被误判“源文件已变化”（`import_jobs._guard`）：涉及扫描与关联并发的设计，改动面大，列入待用户决定。
- `media_discovery.split_collection` 只有测试在用（生产无引用）：删除要连测试一起删，列入待用户决定。
- 扫码轮询的服务端 `polled` 检查没加锁（`drives.py`）：影响极小（两次并发轮询才会触发），未改。
- 仍是超椭圆的圆形：`.icon-btn`（显式写了 squircle）、详情页收藏按钮、版本播放按钮、`btn-link.small`。`.icon-btn` 是作者显式指定的，没动。

按影响排序：
