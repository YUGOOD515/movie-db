# 本地影视库数据库数据字典

## 1. 数据库结构概览

数据库以 `title_basic` 为核心。电影、剧集和单集统一视为 `title`，其他数据通过 `title_id` 或其下级实体关联。

| 表名 | 用途 |
|---|---|
| `title_basic` | 存储电影、剧集、单集共同拥有的基础影视信息，是整个数据库的核心表。 |
| `title_relation` | 存储 episode 与 series 之间的从属关系，以及季号、集号。 |
| `title_artwork` | 存储 title 对应的 Logo、横版海报、竖版海报和单集剧照。 |
| `media_file` | 存储 movie / episode 对应的实际 AList 视频文件及媒体技术信息。 |
| `playback_progress` | 每次观看生成一条记录，保存该次观看的播放进度和观看时间。 |
| `collection` | 存储系统收藏夹及用户自定义收藏夹。 |
| `collection_item` | 存储收藏夹与 title 之间的多对多关系。 |

整体关系：

```text
title_basic
├── title_relation
├── title_artwork
├── media_file
│   └── playback_progress
└── collection_item
    └── collection
```

# 2. `title_basic`

存储所有 movie、series、episode 的基础信息，`title_id` 统一使用 IMDb `tconst`。

| 字段 | 类型 | `movie.db` 对应来源 | 用途 |
|---|---|---|---|
| `title_id` | `TEXT PRIMARY KEY` | `media.imdb_id` | 存储 IMDb `tconst`，如 `tt0816692`，作为整个影视库统一的 title 标识。 |
| `tmdb_id` | `INTEGER` | `media.tmdb_id` | 存储 TMDB 作品 ID，用于调用 TMDB API 补充数据和匹配；允许为空。 |
| `title_type` | `TEXT NOT NULL` | `media.media_type` | 存储 title 类型，项目内统一为 `movie`、`series`、`episode`。 |
| `primary_title` | `TEXT` | 无；来自 IMDb `title.basics.primaryTitle` | 存储 IMDb 使用的主要标题。 |
| `original_title` | `TEXT` | 无；来自 IMDb `title.basics.originalTitle` | 存储作品原始语言标题。 |
| `original_language` | `TEXT` | `tmdb_metadata.original_language` | 存储作品原始语言的 ISO 639-1 代码，如 `en`、`ja`、`zh`。 |
| `display_title` | `TEXT NOT NULL` | `media.display_title` | 存储网站最终显示的标题，通常用于人工确定的中文标题。 |
| `is_adult` | `INTEGER NOT NULL DEFAULT 0` | 无；来自 IMDb `title.basics.isAdult` | 标记 IMDb 是否将该 title 归为成人内容，使用 `0/1`。 |
| `start_year` | `INTEGER` | 无；来自 IMDb `title.basics.startYear` | 存储电影上映年份或剧集首播年份。 |
| `end_year` | `INTEGER` | 无；来自 IMDb `title.basics.endYear` | 存储 series 完结年份；电影和未完结 series 通常为空。 |
| `runtime_minutes` | `INTEGER` | 无；来自 IMDb `title.basics.runtimeMinutes` | 存储 IMDb 标称片长，不代表本地实际视频文件时长。 |
| `genres` | `TEXT` | 无；来自 IMDb `title.basics.genres` | 存储 IMDb 类型信息，如 `Drama,Sci-Fi`。 |
| `overview` | `TEXT` | `tmdb_metadata.overview` | 存储影视内容简介；以后即使数据来自 TMDB，也直接写入本表。 |
| `tagline` | `TEXT` | `tmdb_metadata.tagline` | 存储电影或剧集的宣传语 / tagline。 |
| `average_rating` | `REAL` | 无；来自 TMDB API `vote_average`，旧库未落库 | 存储 TMDB 加权平均评分，范围 0–10，保留一位小数。 |
| `num_votes` | `INTEGER` | 无；来自 TMDB API `vote_count`，旧库未落库 | 存储 TMDB 参与评分的投票人数。 |
| `added_at` | `TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP` | `media.created_at` | 记录该 title 加入个人影视库的时间，可用于“最近添加”。 |
| `updated_at` | `TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP` | `media.updated_at`；原 `tmdb_metadata.synced_at` 可在迁移时合并考虑 | 记录本地 title 信息最近一次修改时间。 |

### 约定

`title_type` 不直接使用 IMDb 的 `tvSeries`、`tvEpisode` 命名，而在网站数据库中规范化：

```text
IMDb             本地
movie       →    movie
tvSeries    →    series
tvEpisode   →    episode
```

`display_title` 与 `primary_title` 分开。前者属于你的个人影视库展示逻辑，后者属于 IMDb 元数据。

# 3. `title_relation`

只存储 episode 与 series 的层级关系，不重复保存 title 自身信息。

| 字段 | 类型 | `movie.db` 对应来源 | 用途 |
|---|---|---|---|
| `episode_id` | `TEXT PRIMARY KEY` | episode 对应的 `media.imdb_id` | 存储该 episode 的 IMDb `title_id`，同时关联 `title_basic.title_id`。 |
| `series_id` | `TEXT NOT NULL` | `media.parent_media_id → media.media_id → media.imdb_id` | 存储该 episode 所属 series 的 IMDb `title_id`。 |
| `season_number` | `INTEGER` | `media.season_number` | 存储该单集所属季号。 |
| `episode_number` | `INTEGER` | `media.episode_number` | 存储该单集在对应季中的集号。 |

### 关系

```text
episode_id → title_basic.title_id
series_id  → title_basic.title_id
```

建议约束：

```sql
PRIMARY KEY (episode_id)
UNIQUE (series_id, season_number, episode_number)
```

因此 `title_basic` 不再需要：

```text
parent_media_id
season_number
episode_number
```

# 4. `title_artwork`

统一存储 title 的所有图片资源。

| 字段 | 类型 | `movie.db` 对应来源 | 用途 |
|---|---|---|---|
| `title_id` | `TEXT NOT NULL` | `media_image.media_id → media.imdb_id` | 标记图片属于哪个 movie、series 或 episode。 |
| `artwork_type` | `TEXT NOT NULL` | `media_image.image_type` | 存储图片类型。 |
| `position` | `INTEGER NOT NULL` | `media_image.image_position` | 同一种图片存在多个候选时记录排序位置。 |
| `remote_path` | `TEXT` | `media_image.remote_path` | 保存图片的远程来源路径或 URL，允许为空。 |
| `local_path` | `TEXT NOT NULL` | `media_image.local_path` | 保存实际使用的本地图片路径。 |

建议复合主键：

```sql
PRIMARY KEY (title_id, artwork_type, position)
```

`artwork_type` 统一定义为：

| 值 | 含义 | 原 `movie.db` |
|---|---|---|
| `poster` | 竖版海报 | `poster` |
| `landscape_poster` | 横版海报 | `backdrop` |
| `logo` | 透明 Logo | `logo` |
| `still` | Episode 单集剧照 | `still` |

一般业务规则：

```text
movie  → poster / landscape_poster / logo
series → poster / landscape_poster / logo
episode → still
```

# 5. `media_file`

存储实际存在于 AList 中的视频文件，以及 ffprobe 等工具得到的媒体技术信息。

| 字段 | 类型 | `movie.db` 对应来源 | 用途 |
|---|---|---|---|
| `file_id` | `INTEGER PRIMARY KEY` | `media_source.source_id` | 本地实际媒体文件的唯一标识。 |
| `title_id` | `TEXT NOT NULL` | `media_source.media_id → media.imdb_id` | 标记该视频文件对应哪个 movie 或 episode。 |
| `alist_path` | `TEXT NOT NULL UNIQUE` | `media_source.alist_path` | 存储文件在 AList 中的源路径，用于获取或播放实际媒体文件。 |
| `duration_ms` | `INTEGER` | `media_source.media_duration_ms` | 存储实际视频文件总时长，单位毫秒。 |
| `file_size_bytes` | `INTEGER` | `media_source.file_size_bytes` | 存储视频文件大小，单位字节。 |
| `bit_rate` | `INTEGER` | `media_source.bit_rate` | 存储视频文件总体码率。 |
| `container_format` | `TEXT` | `media_source.container_format` | 存储文件封装格式，如 `mkv`、`mp4`。 |
| `video_codec` | `TEXT` | `media_source.video_codec` | 存储视频编码格式，如 `h264`、`hevc`、`av1`。 |
| `video_width` | `INTEGER` | `media_source.video_width` | 存储视频画面宽度。 |
| `video_height` | `INTEGER` | `media_source.video_height` | 存储视频画面高度。 |
| `video_frame_rate` | `REAL` | `media_source.video_frame_rate` | 存储视频帧率。 |
| `video_pixel_format` | `TEXT` | `media_source.video_pixel_format` | 存储视频像素格式，如 `yuv420p10le`。 |
| `video_dynamic_range` | `TEXT` | `media_source.video_dynamic_range` | 存储 SDR、HDR10、HDR10+、Dolby Vision 等动态范围信息。 |
| `audio_codec` | `TEXT` | `media_source.audio_codec` | 存储主要音轨编码格式。 |
| `audio_channels` | `INTEGER` | `media_source.audio_channels` | 存储主要音轨声道数量。 |
| `audio_channel_layout` | `TEXT` | `media_source.audio_channel_layout` | 存储主要音轨的声道布局，如 `5.1`、`7.1`。 |
| `probed_at` | `TEXT` | `media_source.probed_at` | 记录最近一次读取该文件媒体元数据的时间。 |

关系：

```text
media_file.title_id → title_basic.title_id
```

`title_basic.runtime_minutes` 与这里的 `duration_ms` 不重复：

```text
runtime_minutes = IMDb 对作品的标称片长
duration_ms      = 实际媒体文件的真实时长
```

# 6. `playback_progress`

每一次实际观看都生成一条独立记录，用于同时保存播放进度和完整观看历史。

| 字段 | 类型 | `movie.db` 对应来源 | 用途 |
|---|---|---|---|
| `playback_id` | `INTEGER PRIMARY KEY AUTOINCREMENT` | 无，新增字段 | 唯一标识一次观看记录，使同一文件可以拥有多条历史记录。 |
| `file_id` | `INTEGER NOT NULL` | 原 `watch_progress.media_id` 需通过 media → media_source 转换 | 标记本次观看针对哪个实际媒体文件。 |
| `position_ms` | `INTEGER NOT NULL DEFAULT 0` | `watch_progress.position_ms` | 保存本次观看结束或暂停时的播放位置，单位毫秒。 |
| `watched_at` | `TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP` | `watch_progress.updated_at` | 保存这一次观看记录发生的时间。 |

关系：

```text
playback_progress.file_id → media_file.file_id
```

同一 movie / episode 可以存在：

```text
playback_id  file_id  position_ms  watched_at
1            100      842000       2026-08-01
2            100      7210000      2026-08-05
3            100      103000       2026-08-20
```

因此：

- “观看历史”查询全部记录；
- “当前进度”取该 title 最新一条 `watched_at`；
- series 本身不保存播放进度，而是查询其所有 episode 最新的观看记录。

原 `watch_progress.duration_ms` 不再保存，因为实际总时长已经存在：

```text
media_file.duration_ms
```

是否看完可以根据：

```text
position_ms / media_file.duration_ms
```

按业务规则动态判断，不额外存储重复状态。

# 7. `collection`

存储系统自带收藏夹和用户创建的收藏夹。

原数据库的 `folder_type` 同时承担“电影/电视剧范围”，`is_system` 又承担“是否系统收藏夹”。新结构将这两个概念分开。

| 字段 | 类型 | `movie.db` 对应来源 | 用途 |
|---|---|---|---|
| `collection_id` | `INTEGER PRIMARY KEY` | `favorite_folder.folder_id` | 收藏夹唯一标识。 |
| `name` | `TEXT NOT NULL UNIQUE` | `favorite_folder.folder_name` | 存储收藏夹显示名称。 |
| `collection_type` | `TEXT NOT NULL` | 主要由 `favorite_folder.is_system` 转换 | 标识收藏夹本身的类别，如 `system` 或 `custom`。 |
| `title_type` | `TEXT` | `favorite_folder.folder_type` | 限定收藏夹针对的 title 类型，如 `movie`、`series`；不限制时为空。 |
| `icon_name` | `TEXT` | `favorite_folder.icon_name` | 存储收藏夹对应的图标名称。 |
| `order` | `INTEGER NOT NULL` | `favorite_folder.folder_position` | 控制收藏夹在前端中的排列顺序。 |
| `created_at` | `TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP` | `favorite_folder.created_at` | 记录收藏夹创建时间。 |

例如当前数据库：

```text
电影收藏
folder_type = movie
is_system   = 1
```

迁移后：

```text
collection_type = system
title_type      = movie
```

电视剧收藏：

```text
collection_type = system
title_type      = series
```

普通用户新建收藏夹可以是：

```text
collection_type = custom
title_type      = NULL
```

> 注意：`ORDER` 是 SQL 关键字。按当前命名要求字段写作 `order`；SQLite SQL 中建议使用 `"order"` 引用。若尚未正式建表，`sort_order` 在工程上会更省事。

# 8. `collection_item`

存储 title 与 collection 的多对多对应关系。

| 字段 | 类型 | `movie.db` 对应来源 | 用途 |
|---|---|---|---|
| `collection_id` | `INTEGER NOT NULL` | `favorite_item.folder_id` | 标记 title 被加入哪个收藏夹。 |
| `title_id` | `TEXT NOT NULL` | `favorite_item.media_id → media.imdb_id` | 标记被收藏的 movie 或 series。 |
| `added_at` | `TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP` | `favorite_item.added_at` | 记录该 title 加入此收藏夹的时间。 |

建议复合主键：

```sql
PRIMARY KEY (collection_id, title_id)
```

关系：

```text
collection_item.collection_id → collection.collection_id
collection_item.title_id      → title_basic.title_id
```

原来的：

```text
favorite_item.favorite_item_id
```

不再需要，因为 `(collection_id, title_id)` 本身已经能够唯一确定一条收藏关系。

# 9. `movie.db` 迁移关系总表

| 原表 | 新表 | 处理方式 |
|---|---|---|
| `media` | `title_basic` | title 身份和通用字段迁入核心表。 |
| `media` | `title_relation` | `parent_media_id / season_number / episode_number` 从核心表中拆出。 |
| `media_image` | `title_artwork` | 基本整体迁移，`backdrop` 重命名为 `landscape_poster`。 |
| `media_source` | `media_file` | 基本整体迁移，`source_id` 改为 `file_id`。 |
| `watch_progress` | `playback_progress` | 从“一部影片一条状态”改为“一次观看一条历史记录”。 |
| `favorite_folder` | `collection` | 收藏夹概念统一；`is_system` 合并进 `collection_type`。 |
| `favorite_item` | `collection_item` | 移除无必要的 `favorite_item_id`。 |
| `media` + `tmdb_metadata` | `title_basic` | 保留 `overview`、`tagline`、`original_language`、`average_rating`、`num_votes` 及 `media.tmdb_id`，不再保留独立 TMDB 表。 |

# 10. 明确取消的旧字段

| 旧字段 | 处理 |
|---|---|
| `media.media_id` | 删除，以 IMDb `title_id` 作为统一身份。 |
| `media.tmdb_id` | 移入 `title_basic.tmdb_id`，不作为数据库实体标识，仅用于 TMDB API 调用。 |
| `media.parent_media_id` | 改由 `title_relation.series_id` 表达。 |
| `media.season_number` | 移入 `title_relation`。 |
| `media.episode_number` | 移入 `title_relation`。 |
| `media.match_status` | 删除，假设所有 title 已正确匹配 IMDb。 |
| `tmdb_metadata.original_language` | 移入 `title_basic.original_language`。 |
| `tmdb_metadata.homepage` | 删除。 |
| `tmdb_metadata.status` | 删除。 |
| `tmdb_metadata.air_date` | 删除。 |
| `tmdb_metadata.synced_at` | 不再单独保存，可由 `title_basic.updated_at` 承担更新时间语义。 |
| `watch_progress.duration_ms` | 删除，统一读取 `media_file.duration_ms`。 |
| `favorite_folder.is_system` | 删除，由 `collection.collection_type = 'system'` 表达。 |
| `favorite_folder.folder_position` | 改为 `collection.order`。 |
| `favorite_item.favorite_item_id` | 删除，使用复合主键。 |

# 11. 核心设计原则

整个数据库只保留五类概念：

```text
title_basic       → 它是什么
title_relation    → 它属于谁
title_artwork     → 它长什么样
media_file        → 我实际拥有什么文件
playback_progress → 我每次看到了哪里
collection        → 我如何组织这些 title
```

电影、电视剧和单集不再分别拥有独立的数据模型。除了剧集层级和是否存在实际媒体文件之外，它们全部通过同一套 `title_id` 关系参与查询。
