# 前端设计

页面在服务端由 Jinja 渲染，前端用 HTML、CSS、原生 JavaScript 和 Bootstrap 5.3。本文只记录读代码不容易看出的设计决定和原因；交互细节（底部状态栏、弹窗、动效）见[开发 · 前端约定](../zh-CN/development.md#前端约定)。

## 组件选择

- 先找 Bootstrap 原生组件和工具类（按钮、表单、下拉、弹窗、offcanvas、toast、间距类），找不到再写自定义 CSS。自定义 CSS 只用于媒体展示（海报卡片、轨道、详情页头部）和 Bootstrap 没有的交互。原因：样式表已经很大，原生组件能自动适配深浅色和无障碍。
- 模板只负责显示。卡片、徽章、进度、文案在 `viewmodels/` 里准备好，模板里不做计算和拼接，这样只读快照和本机页面能共用同一套模板。
- 颜色写成 `style.css` 里的变量，并在 `[data-bs-theme="light"]` 下给出浅色值；只写深色值会让浅色主题出问题。
- 强调色是中性单色 `--media-accent`：深色主题白色，浅色主题近黑（白色在浅底上看不见），勾和圆点用 `--media-accent-contrast`。Bootstrap 的聚焦、选中、激活色在编译时写死为蓝色，不随变量变化，所以统一在 `style.css` 顶部的 Accent 覆盖层改成强调色。这是对“优先用原生组件”的补充：组件照用，新用到的组件露出蓝色时补进覆盖层，不在页面里局部覆盖，也不为此另写组件。

## 网格与间距

目标：同一页上的卡片、标题和控件落在几条固定的竖线上。

### 主对齐线

页面内容包在 `container-xl` 里，容器的左右内边缘就是主对齐线：页头标题、区块标题、卡片网格、轨道里的第一张卡片都从这里开始。只有横向轨道和详情页背景图会越过容器边缘（出血）。

### 卡片水平间距

全站只有一套卡片间距：

| 视口宽度 | 间距 | 卡片网格 | 横向轨道 |
|---|---|---|---|
| < 992px | 1rem | `g-3` | `gap-3` |
| ≥ 992px | 1.5rem | `g-lg-4` | `gap-lg-4` |

- 同一页上下相邻的网格和轨道用同一档间距，卡片的左右边缘才能连成竖线。
- `.media-rail` 的 `--rail-gap` 用来算卡片宽度和轨道末尾的留白，真正的间距来自模板里的 `gap-*`。两处数值要一起改，只改一处会让卡宽、留白和卡片间距对不上。

### 横向轨道一律露出半张

任何宽度下，轨道右侧都要露出下一张卡片的一部分，作为可以横向滑动的提示（不用底部滚动条或指示线）。

- 卡片宽度按带小数的“可见张数” `--rail-count` 计算：宽度 = (轨道宽 + `--rail-edge-space` − 间距 × (张数 − 1)) ÷ 张数。从第一张卡片左缘到屏幕右缘正好放下这么多张，小数部分就是露出的那一截。首页的 `media-rail--span-*` 和详情页的剧集、演员轨道都这样算，各断点的张数写在 `style.css` 里。
- 张数的小数部分保持在 0.2–0.6 之间。不要取整数，整数会让卡片正好排满、看不出能滑动。演员卡是剧集卡的一半宽，可见张数是剧集的两倍，所以剧集张数的小数也不能是 .5。
- 第一张卡片仍从容器左缘开始；轨道开启 `scroll-snap`（proximity），停下时对齐到卡片边缘。
- 鼠标设备上，区块标题右侧有左右翻页按钮（`_ui.html` 的 `rail_nav`，`rails.js`），一次翻过当前完整可见的卡片，到头时禁用；轨道放得下或在触屏设备上不显示。
- 详情页内部统一 1rem（`gap-3`），与 `--grid-gap` 一致。

### 12 栏精确定宽

需要按栏定宽的区域（详情页头部等）用容器查询计算（剧集、演员轨道的卡宽改按上面的可见张数计算，但同样依赖这里的容器）：

```css
--grid-gap: 1rem;
--grid-col: calc((100cqi - 11 * var(--grid-gap)) / 12);
```

- 先给容器加 `container-type: inline-size`，并登记在 `style.css` 的“Grid containers”选择器里；没有容器时 `100cqi` 会退回视口宽度，算出来的宽度就错了。
- 跨 N 栏 = `N × --grid-col + (N − 1) × --grid-gap`，例如 3 栏写成 `calc(var(--grid-col) * 3 + var(--grid-gap) * 2)`。不要用百分比或固定 px 估算宽度。
- 与栏宽相关的高度也从栏宽派生（如 `--btn-unit-height: calc(var(--grid-col) / 2)`），让比例随宽度一起变化。

### 垂直间距与令牌

- 垂直间距用 Bootstrap 间距类（`mb-*`、`gy-*`）；区块之间用留白分隔，不加分隔线或边框。
- 新尺寸先在 `style.css` 顶部加令牌再使用（圆角 `--radius-*`、阴影、动效曲线等），不要在规则里散写数值。

## 圆角与曲率（G2）

G2 指轮廓连接处切线方向和曲率连续。全站常规圆角矩形以此为设计目标，统一使用 `border-radius` 配合超椭圆形状 [`corner-shape: squircle`](https://www.w3.org/TR/css-borders-4/#propdef-corner-shape)；只设置半径不能表达这项形状约定。

- 适用范围：卡片、海报与缩略图外框、普通按钮、输入框、选择器、菜单、弹窗、抽屉和状态栏等站内圆角矩形容器。管理页与媒体展示页使用同一规则，深浅色主题一致。
- 半径按元素用途复用 `--radius-card`、`--radius-control` 等现有令牌；形状统一不要求所有元素使用同一半径。
- 子元素贴合父级圆角时，形状一并设置 `corner-shape: inherit`，半径扣除父级边框宽度，避免悬停底色或图片在四角露缝。
- 几何例外：状态点、进度环、播放按钮、轨道翻页按钮等明确要求正圆的元素，以及半圆两端的胶囊形组件（如后台任务圆钮、进度条），保留圆形或圆弧。胶囊不追求 G2：`corner-shape` 只在半径框内改曲线，胶囊的半径框就是半个高度，换成任何超椭圆都会把两端压扁；Figma 的圆角平滑在胶囊上同样失效、退回圆弧，Apple 的连续胶囊是系统私有算法，网页上没有官方支持的等价写法。覆盖全站控件默认形状时显式设置 `corner-shape: round`；仅使用 `--radius-pill` 不代表自动豁免。
- 系统原生弹出界面、图标、Logo 和图片内部图形不在这项容器轮廓规范内。
- 兼容性例外：不支持 `corner-shape` 的浏览器保留 `border-radius` 普通圆角回退，不要求回退轮廓满足 G2。

## 管理页 Design system

设置页和源数据页的来源管理共用 `style.css` 中“Design system”一段的 `ui-*` 类。新的管理类页面直接复用这些类，不另写一套。

### 管理工作区

- 侧栏“管理”下分“个性化”（`/media`，已入库作品的图片、评分与失效文件）、“源数据”（`/media/sources`，网盘来源与文件关联）和“设置”。两个管理页的页头一致：左边 h3 标题，右边是筛选框和分段控件（个性化是类型筛选，源数据是关联状态切换），后者只在列表视图可用，核对或看详情时隐藏但保留位置。
- 个性化、源数据、设置与收藏等页面共用 `container-xl` 的左右主对齐线。源数据与设置不单独增加外层 padding 或最大宽度；宽屏利用率通过容器内部的分栏提高。
- `.management-layout` 的左侧导航宽 17rem，992–1199px 为 15rem，右侧 `minmax(0, 1fr)`；栏间距 1.5rem。源数据左栏从上到下：整行的“添加网盘”按钮（菜单里是添加网盘和从 AList 导入）、“全部来源”及其右侧的扫描按钮（扫描全部已配置目录）、各个连接、底部单独一项“已忽略”。每个连接一行：网盘 logo（`static/icons/drives/` 中按类型前缀取品牌，没有时用通用图标）加账号名，没有账号时用挂载名，挂载名和类型放在悬停提示里；正常不额外显示状态，异常用红色及图标标记。左栏同一时间只高亮一项：打开连接详情或查看已忽略时，“全部来源”和目录的选中态收起。点击名称（支持右键）在右侧打开连接详情，查看状态和连接信息、检测、直接修改配置；启停、透传和删除只放在详情标题右侧的“⋯”里，左栏每个连接不再单独放“⋯”。连接正常时状态写“正常”，与设置页一致。凭据只显示是否保存，不回显明文。
- 左栏连接下方只列用户主动选择并保存的关联根目录，来源为 `local.db` 的 roots，不从媒体文件父路径推导、不展开其子目录。目录不带图标，文字与连接的账号名落在同一条线上（`--source-pad` + `--source-logo` + `--source-gap`）。目录点击只筛选右侧关联内容；添加、移除目录和自动识别的回退目录都在连接详情的“扫描目录”分组里，右侧列表不再单独提供扫描目录管理。旧 `/media?tab=associate|drives` 跳转到 `/media/sources`。
- “已忽略”不受来源筛选限制，列出全部忽略的目录：所属网盘的 logo、目录名和完整路径，逐个恢复。没有忽略项时这一项隐藏。
- 源数据页不提供手动录入和 JSON 上传；TMDB 搜索弹窗只用于核对时“更换作品”。批量录入接口 `/manager/import/batch` 只保留给开发测试。
- 首次使用（媒体库为空）的四步指引不占版面，用 Bootstrap Popover 浮在当前要点的元素旁：没有网盘指“添加网盘”，没选目录指左栏的网盘，扫描中指进度卡片，可确认时指“确认关联”或状态切换，关联中与完成后指左上角圆钮。目标看不见（手机上左栏在抽屉里）时改指“选择来源”；核对、连接详情等视图和任何弹窗打开时收起。
- 扫描后的“这些目录没有视频，以后跳过”和跳过的结果都放在左上角后台任务圆钮里（`TaskCenter.result` / `progress`），不在列表上方另起提示条。

- 连接详情与设置页用同一套分组写法（`ui-group`、`ui-status`）：标题下一行是状态，后面接类型、账号、挂载路径和续期，没有的项不写；检测失败的原因、路径不可用、透传里有同名目录等需要处理的情况逐条写在下面。标题右侧只有“检测”和“⋯”。下方直接复用原网盘配置表单，字段直接可改，有改动时才出现“放弃 / 检测并保存”，放弃恢复原值，保存仍走检测后保存流程。扫描目录是第二个分组，目录列在卡片里。网盘类型与挂载名不可修改，不在可编辑字段中重复展示。扫码、网页授权、凭据与高级选项的图标和流程保持一致；添加新连接仍使用原弹窗。
- 小于 992px 时，关联来源使用 Bootstrap `offcanvas-lg`，关闭时不占据布局高度；设置分类改为横向导航。来源抽屉关闭后再打开登录、编辑或目录弹窗，避免多个遮罩叠加。
- 来源选择只改变当前显示和批量操作的文件范围，不触发扫描；路径按完整目录边界匹配，`/夸克` 不包含 `/夸克2`。重新扫描按钮明确扫描全部已配置目录。
- “已关联”从媒体库实际文件映射读取，按作品聚合并在当前来源下展示文件与季集；扫描失败不改变既有关联。核对与已关联详情只替换右侧内容，返回保留来源、状态和列表位置。
- 设置页始终单列，表单行标签在左、控件在右。不把分组并成两列：两列会让 C、D 两条对齐线各出现两条，阅读顺序不唯一，分组不等高时上下间距也对不齐；需要省高度时在行内横向排开，或把不常改的项收进“高级选项”。
- 设置标题归入左侧分类导航，不保留全局副标题；分类的选中态与关联页左栏相同（浅灰底），不用实心强调色。桌面端设置工作区占据可用视口高度，左栏固定展示，右侧表单独立滚动；切换分类回到右侧顶部，保存状态栏仍固定在底部。小于 992px 时分类转为顶部导航并恢复整页滚动。分组间用 3rem 留白，组标题与表单之间 1rem，状态栏留白仅在表单末尾保留一份。

| 对齐线 | 位置 | 落在这条线上的元素 |
|---|---|---|
| A | 页面内容左缘 | 页头标题、分组卡片外缘 |
| B | A + `--ui-inset`（20px） | 分组图标块、行标签、分隔线、按钮行文字 |
| C | 12 栏中第 6 栏起点 | 所有输入控件的左缘 |
| D | A 的镜像 | 检测按钮、开关、输入框右缘 |

- `ui-row` 是 12 栏网格：标签占 5 栏、控件占 7 栏，所以每张卡片的控件都从 C 线开始。
- 层级：页头（h3）→ 分组标题（1rem / 600）→ 行标签（0.9375rem / 500）→ 说明（0.8125rem / 次要色）。
- 设置页和连接详情的状态写在分组标题下一行（`ui-status`），右侧只放操作。只有圆点带状态色，文字用次要色；所有分组的状态都从标题文字这条线开始，不随标题长短错位。正常时统一写“正常”（`services/settings.py` 的 `OK`），补充信息放在“·”后面；未配置 / 已关闭为灰色，异常写具体原因，不另造“已就绪”“已开启”之类的词。
- 分组不再有常驻的说明文字：用途说明（`Group.description`）只在未配置、已关闭等非正常状态时接在状态后面。检测的进度和结果也写在这一行，提醒逐条接在下面，不另起结果块。
- 清除数据是一条存储条加每项一行（名称、大小），占用大的排在前面，默认都不勾选；包含什么放在悬停提示里。“无法恢复”等警告和输入“清除”的确认只在点击“清除所选…”后的确认弹窗里出现。
- 不常改的配置（网盘速率、扫描、代理等）只放 `.env`，不进设置页；`SECTIONS` 只登记页面上要显示的项。
- 分组之间用 `--ui-group-gap`（40px）留白分开；组内行之间用缩进细线；卡片靠底色区分，不加描边。
- 分区色（`data-hue`）只给图标块和清除数据的存储条用，不表达状态；分区对应的颜色登记在 `services/settings.py` 的 `SECTIONS`，存储条各项的颜色登记在 `services/data_reset.py` 的 `PARTS`。

## 首次引导

- 开场只有标题、说明和“开始”，不列检测结果。
- 还没有真实海报时（开场、片源、TMDB 没连通）页面整体居中，不放灰色占位墙；第一张海报加载出来后 `data-posters` 生效，用 View Transition 换成左文右墙：当前一步的每块内容（标题、说明、按钮行等，宽度跟内容走，两种版式里大小相同）各自从中间滑到左边、逐块错开 30ms，海报墙从右侧淡入滑进来。在 TMDB 弹窗里连通时，等这段动画播完再进入下一步。
- 网盘图标是无边框的圆角矩形底，选中时底色提亮、名称加粗。扫码从上到下是“重新获取”、二维码、扫码说明。
- 主页面只放默认登录方式。“其他登录方式”“高级设置”“使用自己的 TMDB 密钥”都打开居中弹窗（原生 `dialog`，在最上层显示，不受页面层叠影响），在弹窗里直接配置、检测；检测通过就关闭弹窗进入下一步。网盘弹窗打开时把这家网盘的字段、检测结果和“检测并保存”搬进去，原处留同高占位，关闭时放回，所以字段仍在网盘表单里，`drives.js` 照常读取。有两种以上方式时弹窗顶部用分段控件切换。必须填写自己的 TMDB 密钥（没有可用的内置密钥）时，密钥直接放在页面表单里。
- 完成页的标题、说明和按钮在可用高度里居中，TMDB 署名放在底部。
- 引导期间加网盘、IMDb 本地库建好都不触发扫描（`has_scan_scope`）：还没选扫描目录时扫了只会报错，错误会带到源数据页。

## 脚本

- `site.js` 只放全站行为，并通过 `window.*` 暴露公共函数（`appIcon`、`showAppToast` 等）；页面脚本按页拆分（`detail.js`、`manager.js` 等），需要公共能力时复用这些函数。
- 下拉选择给 `<select>` 加 `data-ui-select`：`site.js` 的 `enhanceSelect` 换成 Bootstrap 下拉（`.media-menu`），因为原生弹出列表由系统绘制、和站内菜单不一致。原生 select 保留取值并触发 `change`；脚本直接改 `value` 或选项后调用 `window.syncSelect(select)`。
- 动效集中在 `effects.js`，并在系统开启“减少动态效果”时关闭。后台任务的圆钮展开、叠放海报接续、卡片落下、海报飞入和滑出动画跟着任务状态走，写在 `task-center.js` 里，同样在“减少动态效果”时跳过。
- 文件名识别规则 `filename-rules.js` 有独立测试：`node --test tests/test_filename_rules.cjs`。
- AI 平台预设与模型列表由 `ai-presets.js` 处理，设置页和首次引导共用：选平台时填好接口地址和默认模型，有 API Key 时拉取平台的模型列表作为候选，并换成该平台最新的默认模型；用户改过的模型不覆盖，打开页面时只更新候选、不改已保存的值。

## 第三方库与图标

- 第三方库放在 `static/vendor/` 并在其 README 登记版本，不走 CDN：云端只读快照和离线使用都要能加载。
