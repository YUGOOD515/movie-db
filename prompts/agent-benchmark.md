# 项目提示词：本地影视资源管理网站

> 用途：测试不同 Agent 的全栈开发能力。把本文全文作为任务交给 Agent，并把 `agent-benchmark.env` 复制为新项目根目录的 `.env`。

---

请从零完成一个全栈 Web 项目：一个运行在本机的影视资源管理网站。片源来自本机已安装的 AList（GitHub 开源的网盘挂载程序），影视资料来自 TMDB，评分来自 MDBList，名称识别借助 DeepSeek 大模型，播放调用本机的 MPC-HC。

## 一、技术架构

- **后端**：Python + Flask，页面由 Jinja 模板在服务端渲染。
- **前端**：HTML + Tailwind CSS + 原生 JavaScript，不使用 React、Vue 等前端框架。
- **项目管理**：用 uv 管理依赖和运行（`pyproject.toml` + `uv.lock`），用 git 管理代码，按功能分次提交，提交信息用中文。
- **分层**：采用 MVC 架构，或 Model / Connector / View 分层，二选一，但要分清：
  - Model：数据库读写；
  - Controller / Connector：路由只负责“取数据 → 整理 → 渲染”，不写 SQL，不直接调用外部 API；
  - View：Jinja 模板只负责显示，不做业务计算；
  - 对外部服务（AList、TMDB、MDBList、DeepSeek、MPC-HC）的调用各自单独封装。
- **数据库**：SQLite。媒体资料与本机凭据、缓存分开存放。
- **配置**：密钥写在项目根目录的 `.env`，不提交到 git；设置页修改后写回 `.env` 并立即生效。
- **运行环境**：Windows 11 为主，代码不要写死只能在 Windows 上运行的路径（播放器路径等放进配置）。
- 有基本的自动化测试，至少覆盖名称识别与匹配逻辑、外部接口的解析逻辑（用假数据，不依赖网络）。
- 提供 README，写明如何安装、启动、配置和运行测试。

## 二、本机环境

| 项目 | 说明 |
|---|---|
| AList | 安装在 `C:\alist`，服务地址 `http://127.0.0.1:5244`，账号密码见 `.env` |
| 网盘 | AList 中已挂载夸克网盘和百度网盘，里面有电影与剧集文件 |
| 播放器 | `C:\Program Files\MPC-HC\mpc-hc64.exe` |
| TMDB | 只读访问令牌（Bearer Token），见 `.env` 的 `TMDB_TOKEN` |
| MDBList | API Key，见 `.env` 的 `MDBLIST_APIKEY` |
| DeepSeek | OpenAI 兼容接口，见 `.env` 的 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`；`LLM_API` 取 `responses` 或 `chat_completions`，决定调用方式 |

`.env` 中某些密钥可能为空或是占位值（如 `to_do`），网站必须能在缺少它们时正常运行，并引导用户补填（见功能 1）。

## 三、功能

### 1. 首次使用引导与密钥配置

- 首次打开网站进入引导流程，逐步引导用户填写：AList 地址与账号、TMDB、MDBList、DeepSeek 的密钥，以及播放器路径。
- 每一步说明该密钥的用途和获取地址，填写后可点“检测”立即验证是否可用，显示成功或失败原因。
- TMDB 和 AList 是必需项；MDBList 和 DeepSeek 可跳过，跳过后相关功能降级（不显示补充评分 / 只用规则识别），并在设置页提示可随时补填。
- 引导完成后仍可在“设置”页修改所有配置，每组配置旁显示当前连接状态。

### 2. 添加影视与资料补全

- 用户可在网站中添加电影或剧集：浏览 AList 目录选择文件或文件夹，系统自动识别对应的 TMDB 作品；也可以手动搜索 TMDB 并指定。
- 识别结果分为“可确认 / 待核对 / 未识别”，用户确认后入库，可以批量确认。
- 入库后获取并保存：
  - 作品：标题（优先中文）、原名、年份、简介、类型、横版背景图、竖版海报、片名 Logo；
  - 剧集的每一季：季海报、季名、集数；
  - 每一集：标题、简介、播出日期、时长、剧照、评分；
  - 评分：TMDB 评分，以及通过 MDBList 获取的 IMDb、烂番茄等多平台评分。
- 同一部剧的文件要按季、集对应到 TMDB 的每一集；对不上的文件留给用户手动指定季集。
- 图片下载到本地缓存，页面不直接引用外链，离线时已入库的内容仍能正常显示。
- 外部接口调用要限速，遇到 429 等限流错误自动退避重试，不能因为一次失败中断整批录入。

### 3. 网盘名称的 AI 识别

夸克、百度网盘里的资源名常被改写来规避审查，例如谐音字、形近字、拼音或首字母缩写、插入符号或空格、繁简混用、加广告前后缀等。网站需要还原原始片名，正确匹配 TMDB。

- 先用规则清洗：去掉广告、分辨率、编码、字幕组等噪声，解析年份、季号、集号。
- 规则无法确定时交给 DeepSeek：提供文件名、所在目录路径和 TMDB 候选结果，让模型推测原始片名及季集。
- AI 给出的结果必须再用 TMDB 搜索校验，不能直接采信模型编造的 ID。
- 识别结果缓存起来，同一文件不重复调用 AI。
- 在识别详情中展示：原始文件名 → 清洗后名称 → 推测的原始片名 → 匹配到的 TMDB 作品，以及判断理由。

### 4. 首页

- 顶部是横版大海报轮播（使用作品的横版背景图），叠加片名 Logo、年份、类型、评分和简介，带“播放”按钮，自动轮播，也可手动切换。
- 点“播放”调用 MPC-HC 播放该作品：电影直接播放；剧集从上次看到的那一集继续，没看过则从第一集开始。
- 轮播下方按分区展示横向滚动的卡片：继续观看（带进度条）、最近添加、电影、剧集、高分推荐等。
- 有搜索，并可按类型、年份、评分筛选。

### 5. 剧集详情页与进度跟踪

- 剧集详情页显示背景大图、Logo、标题、评分、简介、演职员。
- 下方可选择季，选中后用小卡片列出这一季的每一集：剧照、集号、标题、评分、时长、观看进度。
- 点某一集的卡片即可播放该集。
- 进度跟踪：播放后记录每一集的观看进度和是否看完；详情页和首页“继续观看”都要反映最新进度；用户也可以手动标记已看 / 未看。

### 6. 电影详情页

- 显示电影名和电影 Logo（有 Logo 时用 Logo 代替纯文字标题），以及背景图、海报、年份、时长、类型、评分、简介、演职员。
- 同一部电影有多个版本文件（如 1080p 与 4K）时，可以选择播放哪一个。

### 7. 后台管理

- 管理页列出所有已入库的电影和剧集，可搜索、筛选、删除。
- 每部作品可以切换管理：更换 Logo、海报和背景图（从 TMDB 提供的多张候选中选择）、修改显示标题、重新匹配到另一个 TMDB 作品、重新获取资料。
- 剧集可以调整文件与季集的对应关系。
- 设置页修改各项密钥和播放器路径，查看各外部服务的连接状态。

## 四、设计风格

- 参考 Netflix、Apple TV 一类流媒体应用：深色为主，大图沉浸，界面元素克制，让海报和剧照成为主角。
- 同时提供浅色主题，可以切换并记住选择。
- 强调色只用一种中性色（深色主题用白色、浅色主题用近黑色），不要出现默认的蓝色按钮或蓝色聚焦框。
- 卡片在网格和横向轨道中左右对齐成竖线，全站卡片间距统一；横向轨道右侧露出下一张卡片的一部分，提示可以滑动。
- 圆角、阴影、间距统一用设计变量管理，不在各处散写数值。
- 管理页（设置、后台）风格简洁：表单标签在左、控件在右，各分组的控件左缘对齐。
- 响应式：桌面宽屏到手机宽度都能正常使用。
- 有加载状态、空状态（如“还没有添加影视”）和出错提示，后台任务（扫描、录入）显示进度。
- 动效轻量，系统开启“减少动态效果”时关闭动画。
- 界面文案全部用中文。

## 五、交付与验收

完成后应满足以下全部条件：

1. `uv sync` 后用一条命令即可启动网站，浏览器打开后进入首次引导。
2. 引导中填入 `.env` 里的密钥能通过检测；`LLM_API_KEY` 为占位值时，DeepSeek 检测显示失败原因，跳过后网站仍可正常使用。
3. 从 AList 的夸克或百度网盘目录中选择至少一部电影和一部剧集，能识别并入库；至少演示一个经过改写的文件名被还原并匹配到正确作品的例子（无 AI 时也要说明规则识别的结果）。
4. 首页顶部显示横版海报轮播，点“播放”能拉起 MPC-HC 并开始播放网盘中的文件。
5. 剧集详情页能切换季，看到每一集的剧照小卡片、标题和评分；播放某一集后，进度在详情页和首页“继续观看”中更新。
6. 电影详情页显示电影 Logo 和名称。
7. 后台能更换作品的 Logo / 海报 / 标题，并能重新匹配作品。
8. 深色与浅色主题都正常显示，手机宽度下布局不乱。
9. 自动化测试全部通过，git 历史中有分步的中文提交，README 写清楚使用方法。
10. 最后给出一份说明：完成了哪些功能、哪些没有完成或有已知问题、如何验证。
